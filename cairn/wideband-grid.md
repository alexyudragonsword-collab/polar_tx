# 宽带链的采样网格与更新时钟（polar_tx#22，array_tx E1）

## 问题

array_tx 报：FR2 400 MHz 在默认 os 4 上 ACLR2 读高 4.7 dB、DPD 后 ACLR1 读高约 0.5 dB，os 16 收敛；
`nr_dtc().make_waveform` 不把 `oversampling` 传给 `nr_waveform`（已修）。issue 末尾问的是：
**哪个更新时钟代表真实硬件，由 polar_tx 决定。**

## 关键事实：os 原来同时是两样东西

`DTCPMConfig.f_update` 与 `ChainConfig.f_dpa` 默认等于 `fs_bb = bw·os`，所以提高 os 同时把 DTC 和 DPA 换快——
量化噪声摊到更宽的带上、更新时钟镜像推远。这不是网格收敛，是换芯片（下表"读法 T"：到 os 32 也不收敛，
ACLR1 os 32 − os 16 仍差 3.4 dB）。本库对硬件时钟本来就有立场：架构选择器的 `osr = 4`（量化噪声摊到 osr 上，
`test_selector` 钉住），预设文档里的 1.28 GS/s（320 MHz）。**决定：预设的硬件时钟是 4×**（WiFi 4·BW，NR 4·FFT·SCS）。

## 决定（2026-11-16）

- **时钟与网格分开**：`ChainConfig.f_clock`；预设 `update_oversampling`（默认 4）是时钟，`oversampling` 是网格。
  网格细于时钟时，整条数字链（CFR、极坐标分解、DPD、量化与 EFM1 dither、DPA 编码，连同供电推压与记忆模型）
  在时钟上跑，输出零阶保持到网格上（按保持的群延迟前移 (m−1)/2 点，与波形逐点对齐），
  抖动每次更新一个、随码保持，LO 相噪在网格上——**时钟 Nyquist 以下就是时钟速率那份样本，逐 bin 搬过去**，
  只有以上的频带新抽（`DTCPhaseModulator.noise_phase`）。所以提高网格只加保持的下垂与镜像。
- **默认逐位不变**：默认网格 = 时钟，走原路径。指纹（宽带 18 个预设 × DPD × 噪声、18 个 GUI 报告、FIR 预设）
  124/124 与 b007e60 相同，RTL / dp_cal 导出 43 个文件逐字节相同（dsp_ip 手上的向量不动）。
- **语义变化只落在显式传了 `oversampling` 的调用上**：`nr_dtc(oversampling=16)` 以前是 16× 时钟的芯片，
  现在是 4× 时钟在 16× 网格上；`update_oversampling=None` 回到旧行为（与 issue 的复现逐位相同）。
  FIR 预设的 osr 50 是它的硬件速率，传 `None`。
- **outphasing / RF-DAC 不分开**：预设传 `update_oversampling=None`（时钟随网格）；给它们一个细于时钟的网格会
  `NotImplementedError`（分解与合路在网格上、分支在时钟上，不是同一个硬件）。ex22 对它们只做了噪声关的手工保持。
- **报告**：`polartx.grid.grid_disclaimer` 进报告的 `conventions`（三个宿主都显示），口径与 array_tx
  `report.disclaimer_for` 一致——"采样网格未收敛（…偏差…，ex22），不能背书：杂散 / 模板结论只做趋势比较"；
  每次更新 ≥ 4 个网格点写"已收敛"；时钟随网格的拓扑写"未分开/未验证"。
- **默认网格没有提高**（用户的 (c) 要求"把需要的预设的默认 oversampling 调大、文档数字重跑"）。原因：
  提到 16 后 WiFi / NR 的模板判定会因为更新时钟镜像**全部** FAIL（超限 22–26 dB），而镜像是否该在
  ——预设有没有重建滤波、真实芯片的 DPA 时钟是多少——是硬件建模问题，不是网格问题；
  另外全幅模板上的镜像电平到 os 32 才在 0.3 dB 内（离散保持 → 连续 sinc，O(1/m²)）。
  **2026-11-16 用户确认：默认网格先不动**（PR #23 合入后）。文档数字不动、报告挂免责；镜像该不该建模
  （重建滤波 / 芯片 DPA 时钟）仍是开放问题，见 ROADMAP B7。

## 容差（全量运行前写进 ex22）

与 os 16 比：ACLR 0.3 dB、EVM 0.1 dB（array_tx 的）；模板裕量 0.3 dB（本库定，同属功率比）。os 32 与 os 16
同一容差内才算 os 16 收敛。per-tone EVM 与全幅模板裕量是第一次全量运行之后加的（那次看到了下垂和覆盖缺口），
容差沿用同类，没有按数据调。

## 坑（pitfall）

- **固定 nfft 的 ACLR 在细网格上会读坏**：vendored `aclr` 的邻道紧贴信道边缘，nfft 固定 4096 时网格细 4 倍分辨率就粗 4 倍，
  WiFi 80 MHz 在 16× 网格上因此读差 4 dB（方向与物理相反）。`PolarResult.aclr()` 与报告的 PSD 现在按保持倍数放大 FFT。
- **波形生成器不是抽取一致的**：`x16[::4]` 与 `x4` 差 0.74 %（NR 400）/ 0.36 %（WiFi 320）。网格细于时钟时，预设的
  `make_waveform` 先在时钟速率生成、再带限内插到网格，并把更新时刻的样本原样放回——FFT 内插的 1e-15 舍入会让 EFM1
  dither 的累加在某个样本翻一个码（实测 8 符号时出现过 0.003 rad = 1 LSB）。
- **乘性噪声的带内内容不逐 bin 相同**：LO 相噪在时钟 Nyquist 以下逐 bin 相同，但它乘在信号上，高频段的相噪与信号的乘积
  会落回带内（相对 2e-4 / 1.7e-3，WiFi / FR2）。这是物理，不是实现误差；测试只对相噪本身逐 bin 断言。
- **带噪声比网格时，要么同一份噪声，要么多 seed**：旧的手工版每档重抽 LO，EVM 在 os 16/32 间随机差 0.38 dB。
- **全幅模板裁决依赖末值延平的约定**：NR 模板末点在 2.5·BW，镜像在 ≈4.9·BW，FAIL 来自 `MaskSpec.at` 的 `right=` 延平。

## 教训（lesson）

- **先问一个参数控制了几样东西**。array_tx 把 os 当成纯网格是合理的默认，本库的 os 却兼任硬件时钟；收敛研究在两个读法下
  结论完全相反（T 永不收敛，P 在 os 16 收敛）。
- **"os 4 偏保守"不等于"os 4 安全"**：可见带里每个量都偏保守，但网格外有一个 os 4 根本看不到、且超限 20 dB 以上的东西。

- array_tx：vendor 了 `nr_dtc` / `wifi_outphasing` / `wifi_rfdac`。重新 pin 后 `sim.oversampling` 扫描对极坐标链
